### Autopilot-full

**Keep one implementation owner per PR. Separate implementation from the independent verdict on what lands.**

A verdict covers one patch and green CI covers one head. Step 4 runs a full swarm once, and again only for a major change. The patch-id rule in `playbooks/shipping.md` can carry a lane's result, and every new head needs its own green CI.

1. **The operator's gates come first.** The grant covers only the queue's items, so items the operator names as theirs and PRs outside the queue stop at merge-ready. A request to state the plan is not a go.
2. **Spawn one owner per PR, and keep its work where a replacement can find it.** Resolve the forge once for the program. GitHub CLI (`gh`) is the default. If `command -v origin` succeeds and Origin can resolve the repository, use `origin pr` for every PR operation. Otherwise stay on `gh` and record the fallback. Never require Graphite (`gt`).

   In Cursor, each owner is a cloud agent that builds, opens its PR, babysits it to green, and lands it after steps 4 and 5 clear. In Codex, give each owner an [isolated writable worktree](../../../docs/harness/codex.md#independent-writers). The owner implements and tests the change, then hands the worktree diff and evidence to the parent. The parent inspects the diff and handles Git metadata, publication, CI checks, and merge operations within the operator's grant. Follow `opening-a-pr.md` and `babysit.md` for the forge operations in either host. Keep later fix rounds with the same implementation owner.

   Open the PR early so CI and bots run alongside the work. Before declaring it code-ready, run the host's cleanup from `opening-a-pr.md` and the **no-comments** pass. Then rebase onto current trunk and report the code-ready head before self-proof, so verification runs on the base the patch lands on. Report every later head, and merge-ready once self-proof, CI, and babysit are done. Fix rounds stay on that base unless trunk conflicts, breaks CI, or lands a known concurrent change to the same files, because each rebase restarts CI. Run the repo's checks for the touched paths on the committed head before the code-ready push and before a later push that needs a verifier.

   Record the owner, worktree or cloud checkout, and last verified head in the **show-me-your-work** decision trail. Preserve each finished unit before taking the next. Whoever spawns a subagent records its id, state, and a stuck-after runtime from past runs of its kind. The agent that publishes the branch force-pushes only within the operator's grant, with `--force-with-lease` pinned to the SHA it last published or took over. Pause on a push from anyone else.
3. **Run owners in parallel off trunk, never stacked,** so each PR lands on its own.
4. **Swarm-verify once.** A full swarm runs once, at the code-ready head. Another full swarm runs only for new behavior, a redesign, or a large new diff. A rebase, a merge-conflict resolution, or a minor fix gets a single verifier at the new head, and a wording-only change gets none. Fan out independent verifiers at the code-ready SHA per the **swarm** skill. They re-run the gates, prove the behavior on the real surface using the host's UI or CLI verification route from **poteto-mode**, and audit the diff. Require the live lane and inspect its evidence before accepting the verdict.

   Block a PR only for a problem you can show, with a failing run at the head or a doc line the PR made wrong. A problem the PR's base already has, whether trunk or the PR below it in a stack, doesn't block unless the PR copies it or newly reaches it. Only a bug a user would hit, a failed gate, or a wrong shipped doc blocks, and everything else goes in a follow-up.
5. **Land only what you verified against the trunk it lands on.** The agent responsible for forge operations in step 2 handles the merge within the operator's grant. Green CI alone never authorizes a merge. Once the swarm's lanes have started, merge prep rebases onto current trunk, reports the new head, and waits for green CI.

   Right before merging, fetch trunk and ask whether its changes can affect the patch, because rebasing for every trunk move never ends. Rebase and wait for CI when the code that would land was never tested, as with a conflict, a file both sides changed, or a change to which checks run for the PR. A lockfile both sides changed needs no rebase when a frozen install passes on the merge result and the packages the PR changes resolve there as on the head, because that install tests the lockfile that would land, and a failing install means the rebase must repair it. When trunk changed a caller of the patch or something the patch depends on, such as code it calls or a dependency version, run the patch's checks on the merge result and merge on a pass. Otherwise merge. If trunk would force a third rebase past merge prep, hold and report to the root, which sequences the colliding work.
6. **Run the root layer.** Anything that loosens a gate, such as a raised budget or an allowlist entry, needs a verifier's proof and then your fresh countersign, because the owner is the one who wants green. Under a grant that covers approvals, that countersign is the approval, and the owner's record of it points at your countersign for a lane to check. A disabled or soft-failed check always comes out, because it stops guarding every case. Never give or bypass an approval the forge enforces, because no countersign covers it.

   On the operator's go, audit each hour until no delegated work is left. Use `/loop 1h` in Cursor and keep checks in the current session in Codex. Each check re-reads this playbook from trunk and has owners record missing heads or agents. Probe each worker's artifacts. An agent is stuck when it errors, cannot start turns, or misses its recorded progress deadline. Answer agents waiting on input and replace stuck agents. Catch up the operator per **ketchup** when a check changes their situation.
7. **Stand down at once on the operator's stop.** A hold reaches every owner as a zero-writes order. Each reports where it stands and keeps its brief until the operator releases it.

**Reply:** catch the operator up per the **ketchup** skill, covering each PR's state and verdict, what merged, countersigns and why, open operator gates, and parked follow-ups, with links to each PR and the trails.
