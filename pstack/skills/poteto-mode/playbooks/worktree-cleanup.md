### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (principle-build-the-lever). In Codex, pass `--history codex`. It queries Codex App Server for stored thread metadata with exact Git worktree paths as the `cwd` filter. Cursor uses its project transcript directory. Without `-b` the script checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It gets paths from `git worktree list` and classifies each worktree by size, age, merge state, uncommitted work, PR state, and recorded chat activity. `review-history-unknown` means no matching history was found or the history source could not be read.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` or `review-history-unknown` row, check pinned and active chats and their worktree use. In Codex, inspect the scoped chat list and relevant chats, including agents working in sibling worktrees. A recorded `cwd` can miss a worktree reached from another cwd or by an ephemeral agent. In Cursor, inspect the relevant transcripts. Delegate scoped transcript reads when subagents are available (principle-guard-the-context-window). Keep the worktree for review if you cannot establish current usage.
4. Confirm Git state before cleanup. A `safe` candidate has a clean checkout and a commit reachable from the selected base. A PR associated with the branch name is supplementary evidence. Retain `hold-wip`, `hold-untracked`, and `review-git-unknown` candidates until their contents and ownership are resolved. Confirm that the worktree is out of use immediately before removal.
5. Remove each confirmed `safe` candidate with `git worktree remove <path>`. If Git refuses, leave the worktree and report the reason. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, `~/Library/Application Support/Cursor` (`state.vscdb.backup`, and `snapshots/roots/<root>` where a `<root>` named for a folder you opened as a workspace balloons), package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
